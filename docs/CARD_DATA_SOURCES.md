# 카드 상품 데이터 소스 조사

> 조사일 2026-10-30. 대상은 v0 계산기에 필요한 네 필드입니다.
> 결론부터: **카드 혜택 구간과 할인한도를 제공하는 공공 API는 없습니다.**

## 1. 우리가 필요한 것

| 필드                                   | 쓰임                         | 출처 성격  |
| -------------------------------------- | ---------------------------- | ---------- |
| 구간 기준 금액 (`spend_threshold`)     | 다음 구간까지 남은 금액 계산 | 상품설명서 |
| 구간별 할인한도 (`discount_cap`)       | 넘겼을 때 늘어나는 한도 계산 | 상품설명서 |
| 실적 제외 항목 (`excluded_spend_note`) | 입력 안내 문구               | 상품설명서 |
| 근거 조항 (`clause`)                   | 결과 화면의 신뢰 근거        | 상품설명서 |

네 필드 모두 상품설명서 한 장에 있습니다. 문제는 이걸 기계가 읽을 수 있는 형태로 주는 곳이 없다는 점입니다.

## 2. 확인한 소스

### 2.1 금융상품 한눈에 (금융감독원)

- 주소: <https://finlife.fss.or.kr>
- 형태: 웹 + 오픈API (공공데이터포털 연계)
- 공시 대상: 예·적금, 대출, 연금저축, 펀드, 보험
- 카드: **없음**

2016년 보도에 "신용·체크카드 상품 비교 시스템 개선 추진" 언급이 있었지만, 2026년 현재 공시 목록에 카드 상품은 들어와 있지 않습니다. 금리가 숫자 하나로 비교되는 상품과 달리 카드 혜택은 서술형이라 통합공시 형식에 맞지 않기 때문으로 보입니다.

### 2.2 공공데이터포털 「한국산업은행\_카드상품 정보」

- 주소: <https://www.data.go.kr/data/15085690/openapi.do>
- 형태: REST, XML, 무료, 이용허락범위 제한 없음
- 갱신: 실시간 (2021. 7. 30. 이후 데이터)
- 제공 항목: 카드상품명, 카드유형(신용/체크), 연회비, 가입대상, 요약 설명

실제로 호출 가능한 카드 상품 오픈API입니다. 다만 두 가지가 치명적입니다.

1. **구간과 할인한도가 없습니다.** 우리 계산기의 입력값이 전부 여기 없습니다.
2. **발급사가 한 곳입니다.** 산업은행 상품만 있습니다.

형식 참고용으로만 쓸 수 있고, 데이터 소스로는 쓸 수 없습니다.

### 2.3 여신금융협회 카드다모아

- 주소: <https://gongsi.crefia.or.kr/portal/carddamoa/carddamoaList>
- 형태: 웹 화면. **공식 API 없음**
- 내용: 카드사별 상품 정보를 표준화해 비교

가장 그럴듯한 공공 소스입니다. 상품명, 발급사, 연회비, 주요 혜택을 한 화면에서 볼 수 있습니다. 하지만 페이지가 JavaScript로 목록을 불러오는 구조이고, 공개된 API가 없습니다. 내부 Ajax 주소가 있긴 하나 비공식이라 예고 없이 바뀔 수 있고, 이용약관 검토도 필요합니다.

2026년 1월 보도에서는 단종 상품이 섞여 있고 갱신이 멈췄다는 지적이 나왔습니다. v0에서 여기에 의존하면 "계산 결과가 틀렸다"는 문제가 데이터 신선도에서 터집니다.

### 2.4 카드사 상품설명서

- 8개 전업카드사(신한·삼성·현대·KB국민·롯데·하나·우리·BC)와 은행계 카드 상품
- 각 카드사 홈페이지의 상품 안내 페이지에서 PDF 또는 웹 문서로 제공
- 구간·한도·제외 항목·조항 위치가 모두 원문에 있음

**값의 유일한 원본입니다.** 나머지 소스는 후보를 고르는 데만 씁니다.

문제는 표기 방식이 카드사마다 다르다는 점입니다. 같은 "전월 실적 30만 원"도 어떤 카드는 "이용대금", 어떤 카드는 "실적 인정 금액"이라고 쓰고, 제외 항목은 각주에 흩어져 있습니다. 자동 추출이 어려운 이유입니다.

### 2.5 민간 비교 서비스 (카드고릴라 등)

- 주소: <https://www.card-gorilla.com>
- 형태: 웹/앱. 데이터 제휴 또는 크롤링 필요

혜택별 검색이 잘 되어 있어 후보를 고를 때 참고할 만합니다. 상시 수집은 제휴 계약이 필요하고, v0 범위를 넘습니다.

## 3. 공공 API가 없는 이유

1. **공시 형식이 다릅니다.** 금융상품 통합공시는 금리처럼 비교 가능한 단일 수치를 전제로 합니다. 카드 혜택은 "커피 30% 할인, 월 5천 원까지" 같은 서술형이라 표준 스키마로 담기지 않습니다.
2. **카드사별 표기가 제각각입니다.** 전월 실적, 통합 한도, 전용 한도, 캐시백/포인트, 제외 업종. 통일하려면 사람이 판단해야 합니다.
3. **개정이 잦습니다.** 혜택이 분기마다 바뀌는 상품이 있어, 공시 API를 만들어도 신선도 관리 비용이 큽니다.

## 4. v0 큐레이션 절차

10장이면 1인 기준 4~6시간, 2인 교차 검수까지 6~8시간입니다.

1. **후보 10장 선정**
   카드다모아와 카드고릴라에서 국내 발급량 상위 및 검색 노출 상위 상품을 고릅니다. 원 단위 할인형만 넣고 포인트형은 v1로 미룹니다.
2. **상품설명서 확보**
   카드사 홈페이지에서 PDF 또는 웹 문서를 받고, URL을 기록합니다.
3. **네 필드 추출**
   구간 기준 금액, 구간별 할인한도, 실적 제외 항목, 조항 위치(쪽/항). 숫자는 원 단위 정수로 적습니다.
4. **카탈로그 입력**
   `samples/card_products.v0.json`에 넣습니다. `as_of`는 상품설명서 확인일입니다.
5. **교차 검수**
   다른 사람이 원문을 보면서 숫자만 대조합니다. 문장 표현은 검수 대상이 아닙니다.

## 5. 검수 규칙

- 구간은 오름차순이어야 하고, 할인한도는 단조 증가해야 합니다. 감소하는 상품이 있으면 데이터 오류를 먼저 의심합니다.
- 모든 구간에 `clause`가 있어야 합니다. Pydantic 모델이 빈 문자열을 거부합니다.
- 제외 항목은 원문 표현을 최대한 유지합니다. 요약하다 보면 "무이자할부 제외" 같은 핵심이 빠집니다.
- 확인일(`as_of`)이 없으면 카탈로그에 넣지 않습니다.

## 6. 개정 감지 (제안, 미구현)

수작업의 약점은 약관이 바뀌어도 모른다는 점입니다. 비용이 거의 없는 방법이 하나 있습니다.

- `Card`에 `source_url`과 `document_hash`를 추가합니다.
- 주 1회 상품설명서 URL을 받아 해시만 비교합니다.
- 해시가 바뀐 카드만 큐레이션 큐에 올립니다.

문서 전체 해시는 사소한 서식 변경에도 반응합니다. 그래서 해시가 바뀌면 "자동 갱신"이 아니라 "사람이 다시 본다"로 연결해야 합니다.

## 7. v0 범위 결정

- 상품 10장, 원 단위 할인형만
- 포인트형, 연회비 대비 손익, 업종별 추가 할인은 v1
- 데이터는 손으로 큐레이션하고, 출처 URL과 확인일을 남긴다
- 공공 API 연동은 하지 않는다 (연동할 대상이 없다)
