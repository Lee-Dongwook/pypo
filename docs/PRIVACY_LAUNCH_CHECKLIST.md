# 개인정보 처리방침 공개 전 체크리스트

> `docs/PRIVACY_POLICY.md`를 게시하기 전에 확인할 것들입니다.
> 법률 자문이 아닙니다. 유료화·투자·B2B 계약 전에는 변호사 검토를 권합니다.

## 0. 사업자등록과 무관합니다

「개인정보 보호법」 제2조 제5호는 개인정보처리자를 "공공기관, 법인, 단체 및 **개인 등**"으로 정의합니다. 사업자등록 여부는 요건이 아닙니다. 업무 목적으로 개인정보를 처리하는 순간 해당되고, 처리방침 수립·공개 의무도 같이 발생합니다.

정리하면 이렇습니다.

| 항목                 | 사업자등록 전                   | 근거                                 |
| -------------------- | ------------------------------- | ------------------------------------ |
| 개인정보처리자 해당  | 해당                            | 법 제2조 제5호                       |
| 처리방침 수립·공개   | 필요                            | 법 제30조                            |
| 보호책임자 별도 지정 | 불필요. 대표자가 보호책임자     | 법 제31조 제2항, 시행령 제32조 제1항 |
| 사업자등록번호 기재  | 의무 아님                       | 개인정보보호법에 기재 항목이 없음    |
| 사업자 정보 표시     | 유료 판매를 시작할 때 별도 검토 | 전자상거래법                         |

소상공인(「소상공인기본법」 제2조 제1항)은 보호책임자를 따로 두지 않아도 되고, 대표자가 그 역할을 합니다. 다만 처리방침에는 보호책임자의 이름과 연락처가 들어가므로, 개인 이름과 연락처가 공개된다는 점은 감수해야 합니다.

## 1. 채워야 할 값

| `{{1년}}`           | 문의 기록 보관 기간   | 실제 운영 방식과 맞출 것   |

`{{`가 하나라도 남아 있으면 게시하면 안 됩니다. 지금은 자리표시자가 남아 있으면 `/privacy` 상단에 경고 배너가 뜹니다. 배너가 사라졌는지 확인하고 배포하세요.

## 2. 공개 방법

- 시행령 제31조 제2항은 인터넷 홈페이지에 **지속적으로 게재**하도록 정합니다.
- 초기 화면에서 한 번의 클릭으로 닿아야 합니다. 푸터에 "개인정보 처리방침" 링크를 고정합니다.
- 주소는 `/privacy`로 고정하고, 링크를 바꾸지 않습니다.
- 아직 페이지가 없습니다. 배포 전에 `apps/web/app/privacy/page.tsx`를 만들고 모든 화면의 푸터에 링크를 넣어야 합니다.

## 3. 문서와 구현이 맞는지

현재 구현 기준으로 확인한 사실입니다.

| 문서의 서술                 | 구현                                             | 확인                             |
| --------------------------- | ------------------------------------------------ | -------------------------------- |
| 계산 입력값을 저장하지 않음 | API가 DB에 쓰지 않음. 요청 처리 후 응답만 반환   | 사실                             |
| 쿠키를 사용하지 않음        | 쿠키·로컬스토리지 미사용. 상태는 메모리에만 존재 | 사실                             |
| 제3자 제공 없음             | 외부 전송 없음                                   | 사실                             |
| 위탁 없음                   | 호스팅 계약 전                                   | 배포 시 갱신                     |
| 국외 이전 없음              | 배포 전                                          | 해외 리전·해외 SaaS 사용 시 갱신 |

배포하면서 이 중 하나라도 깨지면 문서를 먼저 고쳐야 합니다. 문서가 구현을 따라가는 게 아니라, 구현이 문서를 넘어서면 안 됩니다.

## 4. 갱신이 필요한 순간

아래 중 하나를 하면 `docs/PRIVACY_POLICY.md`를 고치고 다시 게시합니다.

- **알림 신청을 붙일 때**: v0 일정 2주 차에 알림 신청이 있습니다. 이메일이나 전화번호를 받으면 2장(항목), 3장(보유 기간), 7장(철회 방법)이 바뀝니다. 문자 발송을 붙이면 통신사 위탁이 생겨 6장도 바뀝니다.
- **분석 도구를 붙일 때**: GA, Plausible, Amplitude 등 무엇이든 10장과 12장이 바뀝니다.
- **회원가입·로그인·저장 기능을 붙일 때**: 2장과 3장이 크게 바뀝니다. "저장하지 않습니다"라는 문장을 지워야 합니다.
- **결제를 붙일 때**: 2장, 3장, 5장, 6장이 바뀝니다. 전자상거래법 표시 의무도 별도로 생깁니다.
- **호스팅을 해외 리전이나 해외 사업자로 할 때**: 11장에 이전받는 자, 국가, 일시·방법, 항목, 목적, 보유 기간, 거부 방법을 채웁니다.
- **광고를 붙일 때**: 10장과 12장이 바뀝니다. 맞춤형 광고면 행태정보 수집·이용·거부 안내가 추가로 필요합니다.

## 5. 안전성 확보조치 최소선

법 제29조와 같은 법 시행령, 「개인정보의 안전성 확보조치 기준」이 기준입니다. 지금 규모에서 현실적인 최소선은 다음과 같습니다.

- HTTPS 적용 (전송 구간 암호화)
- 접속 기록 보관 기간을 정하고 그 기간만 보관
- 서버 접속 권한을 운영자 1인으로 제한
- 개인정보 처리 시스템에 대한 정기 점검

1만 명 미만 소상공인에 대한 예외는 안전성 확보조치 기준의 일부 항목(내부 관리계획 수립 등)에 한정됩니다. **처리방침 수립·공개 의무 자체가 면제되는 것은 아닙니다.** 이 구분을 혼동하기 쉬운데, 예외를 근거로 방침을 안 올리면 과태료 대상입니다.

## 6. 과태료

처리방침을 정하지 않거나 공개하지 않으면 1천만 원 이하의 과태료가 부과됩니다(법 제75조 제4항 제8호). 2026년 9월 11일 시행 개정으로 보호책임자 지정·신고 관련 과태료가 신설됐습니다. 그중 이사회 의결과 보호위원회 신고 의무는 대통령령이 정한 규모 기준에 해당하는 사업자에게 적용되므로 현재 규모에는 해당하지 않습니다.

## 7. 아직 하지 않은 것

- 운영자 정보와 보유 기간 채우기
- 호스팅 사업자 확정 후 6장·11장 확정
- 접속 기록 보관 기간을 호스팅 정책과 대조
- 처리방침 버전 관리 (변경 이력 남기기)
