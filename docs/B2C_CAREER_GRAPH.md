# B2C 위성 제품: 직무 생존 지도 (가칭)

> 상태: 제품 브리프 v0. 아직 구현 전이며, B2B 온톨로지 플랫폼 위에 올리는 첫 B2C 실험입니다.

## 1. 한 줄 정의

**내 직무의 과업이 AI로 얼마나 바뀌는지 보여주고, 옆 직무와 학습 경로까지 그래프로 안내하는 서비스.**

- 사용자는 온톨로지를 사지 않습니다. “내 직무가 어떻게 변하고, 다음에 뭘 준비해야 하는지”를 삽니다.
- 채팅이 아니라 **지도·경로·근거 카드**가 전면에 나옵니다.
- pypo의 차별점인 관계 추론, 출처, 버전 고정을 소비자 언어로 번역합니다.

## 2. 타깃과 문제

| 항목 | 내용 |
|---|---|
| 1차 타깃 | 25~39세 이직 준비자, AI로 직무 변화를 걱정하는 직장인 |
| 2차 타깃 | 커리어 전환 상담사, 아웃플레이스먼트를 준비하는 기업 (B2B 확장) |
| 핵심 질문 | “내 직무는 AI로 어떻게 바뀌고, 6개월 안에 무엇을 준비해야 하나?” |
| 현재 대안 | 막연한 뉴스, 일반론적인 챗봇 답변, 고가의 커리어 컨설팅 |
| 부족한 것 | 내 직무·과업·스킬을 연결한 개인화된 근거 |

## 3. 30초 경험 (Aha moment)

1. 직무를 검색하거나 이력서를 올린다.
2. 3분 안에 “내 직무 과업 12개 중 5개가 자동화 노출, 인접 직무 3개, 부족 스킬 4개” 카드를 본다.
3. 각 항목을 펼치면 **왜 그런지** 출처와 기준 버전이 보인다.
4. “2026 상반기 기준” 공유 카드를 저장한다.

## 4. 제품 원칙

1. **온톨로지 용어를 노출하지 않는다.** 사용자는 직무, 과업, 스킬, 경로만 본다.
2. **예측이 아니라 노출도로 말한다.** “직무가 사라진다”가 아니라 “이 과업이 자동화에 얼마나 노출됐는지”를 보여준다.
3. **모든 주장에 출처와 기준일을 붙인다.** 출처 없는 점수는 만들지 않는다.
4. **결과는 공유 가능한 한 장으로 끝낸다.** 그래프는 근거를 펼칠 때만 등장한다.
5. **개인 데이터는 사용자 단위 tenant로 격리하고 삭제를 보장한다.**

## 5. MVP 범위

### 만드는 것

| 영역 | MVP |
|---|---|
| 온톨로지 | 직무 30개, 과업 200개, 스킬 300개, 학습 리소스 100개, 한국어 라벨 |
| 관계 | `occupation hasTask`, `occupation requiresSkill`, `task requiresSkill`, `occupation transitionsTo`, `learningResource teachesSkill` |
| 입력 | 직무 검색 선택 (이력서 PDF는 v1.1) |
| 리포트 | 과업별 노출도, 인접 직무, 부족 스킬, 8주 학습 경로, 출처 |
| 화면 | 랜딩 → 직무 선택 → 리포트 → 공유 카드 |
| 인증 | 매직링크 또는 OIDC, 사용자 tenant, 계정 삭제 |
| 분석 | PostHog 이벤트, 리포트 완료율, 공유율 |
| 과금 | MVP에서는 결제 없이 “심층 리포트 신청”으로 지불 의향 측정 |

### 지금 하지 않는 것

- OWL DL 전체 추론, 대규모 문서 적재, 관리자 콘솔
- 이력서 PDF 파싱, 모바일 앱, 자동 결제
- 채용 공고 실시간 크롤링 (약관·품질 리스크)
- “직무 소멸 확률” 같은 단정적 예측

## 6. 온톨로지 스케치

```text
(:Occupation {iri, label_ko, label_en, source, as_of})
  -[:HAS_TASK]->(:Task {iri, label_ko, automation_exposure, source})
  -[:REQUIRES_SKILL {importance}]->(:Skill {iri, label_ko, category})
  -[:TRANSITIONS_TO {distance}]->(:Occupation)

(:Task)-[:REQUIRES_SKILL]->(:Skill)
(:LearningResource {iri, title, provider, url, hours})-[:TEACHES]->(:Skill)
(:Source {iri, name, url, published_at, version})
```

- 노출도는 공개 연구(예: O*NET 과업 단위 분석, OECD AI exposure)와 규칙을 결합해 산출하고, 연구별 기준일을 별도 속성으로 남깁니다.
- 리포트는 생성 시점의 온톨로지 버전을 고정해 재현 가능하게 합니다.
- 관계 추론은 “스킬 전이”와 “선수 관계”에만 먼저 씁니다. LLM은 추출·요약·문장화에만 사용합니다.

## 7. 데이터 소스

| 소스 | 용도 | 비고 |
|---|---|---|
| O*NET | 직무·과업·스킬·능력 | 공개, 영어, 한국어 매핑 필요 |
| ESCO | 직무·스킬 분류, 다국어 | 공개, 유럽 직무 기준 |
| 고용24/워크넷 | 국내 직무·채용 동향 | 공공 API, 약관 확인 |
| KMOOC·공개 강의 | 학습 리소스 | 제공기관 약관 확인 |
| 공개 AI 노출 연구 | 과업 노출도 | 인용·기준일 필수 |

초기에는 크롤링하지 않습니다. 공개 데이터와 수동 큐레이션으로 30개 직무를 먼저 완성합니다.

## 8. 아키텍처 연결

```text
B2C Web (Next.js)
      │
      ▼
FastAPI /career API
      │  report job (Celery)
      ▼
Career Ontology (GraphDB named graph, versioned)
      │ projection
      ▼
Neo4j  ── path / neighbors / analytics
      │
      └── citation · source · as_of
```

- 기존 `GraphDB = 원장, Neo4j = 투영` 구조를 그대로 사용합니다.
- 새 도메인 모듈은 `src/app/career/`에 두고, MCP 도구는 `career.occupation`, `career.path`, `career.report`로 제한합니다.
- B2C 웹은 별도 앱(`web/`)으로 분리해 B2B API와 배포 주기를 독립시킵니다.
- 리포트는 사용자 tenant에 저장하고, 온톨로지 버전과 출처 스냅샷을 함께 보관합니다.
- 1차 구현은 전체 파이프라인 대신 “직무 30개 + 리포트 1종”의 얇은 수직 슬라이스로 시작합니다.

## 9. 과금 가설

| 플랜 | 가격 | 내용 |
|---|---|---|
| 무료 | 0원 | 요약 리포트, 공유 카드, 인접 직무 1개 |
| 심층 | 9,900~29,900원 | 과업별 근거, 전체 학습 경로, 6개월 액션 플랜 |
| 구독 | 월 9,900원 | 직무·시장 변화 알림, 이력서 업데이트 제안 |
| B2B | 별도 | 아웃플레이스먼트, 커리어 상담사 대시보드 |

MVP에서는 결제를 붙이지 않고 “심층 리포트 신청” 버튼으로 지불 의향을 측정합니다.

## 10. 검증 지표

| 지표 | 목표 |
|---|---|
| 랜딩 → 리포트 완료 | 40% 이상 |
| 리포트 공유율 | 10% 이상 |
| 이메일/알림 신청 | 25% 이상 |
| 심층 리포트 지불 의향 | 5% 이상 |
| 리포트 만족도 | NPS 40 이상 |

6주 후 위 지표가 절반도 나오지 않으면 도메인을 바꿉니다. 지표가 나오면 결제와 B2B 확장을 붙입니다.

## 11. 리스크와 완화

| 리스크 | 완화 |
|---|---|
| 공포 마케팅으로 보임 | “생존”보다 “과업 변화”를 전면에, 단정적 예측 금지 |
| 범용 챗봇과 차별이 안 보임 | 그래프 경로, 출처, 기준 버전을 결과물에 고정 |
| 데이터 라이선스 | 공개 데이터 우선, 크롤링 금지, 출처 표시 |
| 콘텐츠 유지비 | 온톨로지 버전과 분기 갱신, 소스별 기준일 관리 |
| 개인정보 | 사용자 tenant, 최소 수집, 삭제 API, 리포트 공유 시 익명화 |
